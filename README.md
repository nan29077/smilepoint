# 스마일 포인트

제휴 웹하드 포인트를 스마일 포인트로 교환하고, 계좌 출금·모바일 쿠폰 쇼핑·포인트 선물에 사용하는 서비스의 **로컬 데모**입니다. 서비스명은 가칭이며 `catalog.js`의 `config`에서 바꿀 수 있습니다.

## 실행

Node.js 22 이상에서 프로젝트 폴더를 열고 다음을 실행합니다. 패키지 설치는 필요 없습니다.

```powershell
npm.cmd run dev
```

브라우저에서 <http://localhost:3070>을 엽니다. 대시보드 상단에 **서버 연결**이 표시되면 실서버 모드입니다.

| 실행 방식 | 동작 |
| --- | --- |
| `npm run dev` (서버 모드) | 회원·거래가 `data/db.json`에 저장되고, 로그인은 HttpOnly 세션 쿠키로 유지됩니다. 비밀번호는 scrypt로 해시합니다. 여러 브라우저·관리자가 같은 데이터를 보고, 처리 결과가 15초 안에 다른 화면에 반영됩니다. |
| GitHub Pages 등 정적 호스팅 (데모 모드) | 서버가 없으면 자동으로 브라우저 저장소에서 동작합니다. 상단에 **데모 모드**가 표시됩니다. |

설정은 `.env.example`을 `.env`로 복사해 바꿉니다. 데모 모드(테스트 계정 로그인·데모 초기화)는 **내 PC(127.0.0.1)에서 실행할 때만** 자동으로 켜지고, 외부에 여는 서버(`HOST=0.0.0.0`, https 주소, `NODE_ENV=production`)는 `DEMO_MODE=on`을 직접 적지 않는 한 운영 모드로 시작합니다.

## 로그인

상단 **로그인**·**회원가입** 버튼으로 들어갑니다.

| 방법 | 설명 |
| --- | --- |
| 소셜 로그인 | 카카오·네이버·Google·Apple 버튼. `.env`에 앱 키가 있으면 실제 로그인, 데모에서는 체험용 회원으로 로그인합니다. 처음 가입하는 경우 약관 동의 화면을 거칩니다. 운영 서버에서는 키를 등록한 방식만 보입니다. |
| 이메일 로그인 | 가입한 이메일·비밀번호로 로그인합니다. 2단계 인증을 켠 운영진은 인증 앱의 6자리 코드도 입력합니다. |
| 테스트 계정 로그인 | 로그인 화면 하단 버튼을 누르면 바로 해당 대시보드로 이동합니다. |

| 테스트 계정 | 이메일 | 비밀번호 |
| --- | --- | --- |
| 사용자 | user@smilepoint.kr | smile1234 |
| 웹하드 관리자 (그린파일) | partner@smilepoint.kr | smile1234 |
| 웹하드 관리자 (클라우드박스) | cloud@smilepoint.kr | smile1234 |
| 최고 관리자 | admin@smilepoint.kr | smile1234 |

회원가입은 이름·이메일·비밀번호·휴대폰·추천인 코드와 필수/선택 약관 동의를 받습니다. 가입 축하 1,000 P(추천 코드 입력 시 +500 P, 추천인에게도 500 P)는 **첫 포인트 교환이 완료되면** 지급합니다 (다계정 가입으로 포인트를 모으는 악용 방지).

## 대시보드 기능

대시보드는 좌측 메뉴로 구성되며, 좌측 하단에 **메인으로** 버튼과 **프로필**이 고정되어 있습니다. 상단에는 알림(읽지 않은 수 표시)과 로그아웃이 있습니다.

**사용자**: 내 지갑(잔액·등급·출석·친구 초대·14일 적립 차트·사용처 차트) · 포인트 교환(웹하드 계정 연결 — 웹하드로 전송된 6자리 인증번호 입력, 교환 신청) · 계좌 출금(1원 인증으로 본인 명의 계좌 등록, 등급별 수수료, 일일 한도) · 포인트 쇼핑(검색·분류·수량) · 쿠폰함(번호 보기 후 바코드, 사용 완료/만료 탭 — 번호를 본 쿠폰은 직접 취소 불가) · 출석체크(월 달력, 7일 연속 보너스) · 포인트 선물 · 거래 내역(필터·CSV) · 고객센터(1:1 문의) · 프로필(동물 캐릭터 30종, 사진 업로드 우선 적용, 알림 설정, 비밀번호 변경, 회원 탈퇴)

**웹하드 관리자**: 자사 개요(대기·승인·처리 시간 지표, 차트, 연동 상태) · 교환 요청(회원 연결 인증번호 목록, 일괄 승인/반려, 완료 30일 이내 회수) · 거래 내역 · 정산 및 대사(기간별, CSV) · API·연동(API 키 보기/복사/재발급, 웹훅 주소·테스트 전송, API 명세, 실제 호출·웹훅 전송 기록) · 교환 정책(일일 승인 한도·2차 승인 기준) · 2단계 인증. 자사 거래만 조회·처리할 수 있고, 회원 이름은 마스킹되어 보입니다.

**최고 관리자**: 운영 개요(회원·심사·출금 지표, 거래 추이, 제휴사 비중, 확인 필요 업무, 최근 가입·관리 기록) · 회원 관리(검색·필터, 회원 상세, 포인트 조정, 이용 정지, 계좌 인증 승인, 탈퇴 회원) · 제휴사 관리(신규 등록·API 키 발급, 교환 비율·최소 금액·일일 승인 한도·2차 승인 기준·운영 상태) · 운영진 계정(생성, 정지, 임시 비밀번호 발급, 2단계 인증 현황) · 연동 관리 · 교환 심사(2차 승인, 교환 회수) · 출금 심사(일괄 처리, 반려 사유 필수, 지급 계좌번호 열람 — 감사 기록) · 전체 거래 · 쿠폰 상품 · 쿠폰 주문 · 정산 및 대사 · 고객센터 답변 · 배너·공지 · 운영 설정(수수료·한도·적립 정책·선물 한도·점검 모드, 데모 초기화) · 감사 기록. 긴 목록은 50건씩 보여 주고 '더 보기'로 늘립니다 (CSV는 전체).

## 서버 API

| 구분 | 주소 | 인증 |
| --- | --- | --- |
| 서비스 | `GET /api/health`, `GET /api/state`, `POST /api/action` | 세션 쿠키 + `X-SmilePoint: 1` 헤더 |
| 제휴사(웹하드) | `GET /api/v1/exchanges?status=pending&limit=100&offset=0` (응답 `next`로 다음 페이지), `POST /api/v1/exchanges/{id}/approve`, `POST /api/v1/exchanges/{id}/reject`, `POST /api/v1/exchanges/{id}/reverse` (완료 30일 이내 회수), `GET /api/v1/link-requests` (회원 연결 인증번호), `GET /api/v1/settlements?date=YYYY-MM-DD`, `POST /api/v1/settlements/{YYYY-MM-DD}` (자사 합계 `{count, amount}` 제출 → 일치/불일치) | `X-Api-Key` (웹하드 관리자 > API·연동에서 확인) |
| 소셜 로그인 | `/auth/kakao`, `/auth/naver`, `/auth/google` | `.env`에 키가 있을 때 실제 OAuth, 없으면 데모 동의 화면 |

회원 연결 인증번호(`member.link_requested`)·연결/해제, 교환 신청·취소·관리자 처리·회수, 테스트 이벤트는 제휴사 웹훅 주소로 전송합니다. 본문은 `X-SmilePoint-Signature: sha256=HMAC(API 키, 본문)`으로 서명하고, 실패하면 30초 간격으로 최대 3회 재시도합니다. 제휴사가 승인한 교환이 **고액(기본 10만 P 초과)이거나 제휴사 일일 승인 한도(기본 100만 P)를 넘으면** 바로 적립하지 않고 최고 관리자 2차 승인으로 넘깁니다 (API 응답 `review.status = "admin_review"`).

서버는 모든 요청에서 역할 권한을 다시 확인하고, 역할별로 볼 수 있는 데이터만 내려보냅니다. 사용자는 자기 거래만, 웹하드 관리자는 자사 교환과 마스킹된 회원 이름만 받습니다. 최고 관리자 화면 데이터에도 API 키 전체·계좌번호 전체·비밀번호 해시·OTP 키·인증번호는 들어가지 않습니다. 로그인은 같은 IP·이메일 5회, 같은 IP 30회, 같은 이메일(여러 IP 합산) 10회 실패하면 잠시 막습니다. 같은 요청이 3초 안에 다시 오면(더블클릭·중복 제출) 한 번만 처리합니다.

## 구조

```
index.html      앱 껍데기
app.js          라우팅, 이벤트, 다이얼로그, 서버/데모 데이터 계층
actions.js      모든 기능 목록(op)과 권한 — 브라우저와 서버가 함께 사용
state.js        데이터 모델과 업무 규칙 (계정·세션·원장·알림·감사 기록·스냅샷)
catalog.js      설정, 제휴사·상품 초기값, 아이콘
views/          화면 (site: 메인·로그인·가입, user/partner/admin: 대시보드, ui: 공통 컴포넌트·차트)
server.mjs      서버 (정적 파일, API, 세션, 제휴사 API, 웹훅, OAuth)
data/           서버 데이터 (Git에 올리지 않음)
```

## 운영 모드와 보안

- `DEMO_MODE=off`로 처음 실행하면 샘플 회원·거래 없이 `ADMIN_EMAIL` 최고 관리자 1명으로 시작합니다. 기존 데이터에 기본 비밀번호(`smile1234`) 계정이 남아 있으면 자동으로 잠그고 로그인 세션도 끊습니다.
- 운영 모드에서는 웹하드 잔액을 임의로 만들지 않습니다. 교환 신청은 제휴사가 자사 장부를 확인해 승인할 때만 적립됩니다.
- 비밀번호를 바꾸거나 관리자가 초기화·정지하면 다른 기기의 로그인이 끊깁니다.
- 웹훅 주소는 https만 허용하고, 내부망·로컬 주소(IPv4 매핑·NAT64·6to4 등 IPv6 우회 표기 포함)는 등록 단계와 전송 직전 DNS 확인 단계에서 모두 막습니다 (DNS 재바인딩 방지).
- 웹하드 계정 연결은 제휴사를 통해 전달되는 6자리 인증번호로 본인을 확인합니다 (10분·5회 제한). 남의 아이디를 입력해도 연결·교환할 수 없습니다.
- 출금 계좌는 1원 인증(입금자명 숫자 4자리, 30분·5회 제한)을 거쳐야 등록되며, 계좌를 등록하면 이름을 바꿀 수 없습니다. `BANK_VERIFY_URL`이 없으면 최고 관리자가 명의를 확인한 뒤 승인합니다.
- 쿠폰 번호는 회원이 '번호 보기'를 누를 때 처음 공개하고, 번호를 본 쿠폰은 회원이 직접 취소할 수 없습니다.
- 운영진은 내 프로필에서 2단계 인증(TOTP — Google Authenticator 등)을 켤 수 있습니다. 최고 관리자가 꺼 두면 운영 개요에 경고가 뜹니다.
- 회원 탈퇴 시 이름·이메일·연락처·계좌·웹하드 연결을 즉시 파기하고, 거래 원장은 익명으로 보관합니다.
- 실패한 요청은 처리 전 상태로 되돌리고, 인증번호 오입력 횟수처럼 남겨야 하는 기록만 저장합니다.
- 가입은 같은 IP에서 1시간 3회로 제한하고, 추천인 보너스는 친구의 첫 교환이 완료된 뒤 지급합니다. 선물은 교환 이력이 있는 회원만, 하루 한도 안에서 보낼 수 있고, 같은 계좌는 한 계정에만 등록됩니다.
- 비밀번호 찾기는 30분짜리 재설정 링크를 만듭니다. `MAIL_WEBHOOK_URL`이 있으면 메일로 보내고, 없으면 서버 로그와 관리자 알림으로 남깁니다(데모 모드에서는 화면에 링크 표시).
- 점검 모드를 켜면 회원가입과 사용자의 교환·출금·구매·선물·출석이 막힙니다.

## 운영 전 남은 일

서버 저장소는 단일 서버용 JSON 파일입니다. 회원이 늘면 PostgreSQL 등 DB로 옮기고, 여러 서버로 늘릴 때는 세션 저장소를 분리합니다. 그 밖에 휴대폰 본인인증(PASS 등), 은행·PG 지급대행 API(1원 인증·자동 이체 — `BANK_VERIFY_URL` 연결), 각 웹하드와의 회원 확인 방식 합의(인증번호 전달 또는 웹하드 OAuth), 기프티콘 공급사 API(실제 쿠폰 사용 여부 확인), Apple 로그인, 선불전자지급수단 등 규제 검토, 약관·개인정보처리방침 법률 검토가 필요합니다.
