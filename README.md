# 스마일 포인트

제휴 웹하드 포인트를 스마일 포인트로 교환하고, 계좌 출금·모바일 쿠폰 쇼핑·포인트 선물에 사용하는 서비스의 **로컬 데모**입니다. 서비스명은 가칭이며 `catalog.js`의 `config`에서 바꿀 수 있습니다.

## 실행

Node.js 22 이상에서 프로젝트 폴더를 열고 다음을 실행합니다. 패키지 설치는 필요 없습니다.

```powershell
npm.cmd run dev
```

브라우저에서 <http://localhost:3070>을 엽니다. 대시보드 상단에 **서버 연결**이 표시되면 실서버 모드입니다.

| 실행 방식 | 동작 |
| --- | --- |
| `npm run dev` (서버 모드) | 회원·거래가 `data/db.json`에 저장되고, 로그인은 HttpOnly 세션 쿠키로 유지됩니다. 비밀번호는 scrypt로 해시합니다. 여러 브라우저·관리자가 같은 데이터를 보고, 처리 결과가 15초 안에 다른 화면에 반영됩니다. |
| GitHub Pages 등 정적 호스팅 (데모 모드) | 서버가 없으면 자동으로 브라우저 저장소에서 동작합니다. 상단에 **데모 모드**가 표시됩니다. |

설정은 `.env.example`을 `.env`로 복사해 바꿉니다. 데모 모드(테스트 계정 로그인·데모 초기화)는 **내 PC(127.0.0.1)에서 실행할 때만** 자동으로 켜지고, 외부에 여는 서버(`HOST=0.0.0.0`, https 주소, `NODE_ENV=production`)는 `DEMO_MODE=on`을 직접 적지 않는 한 운영 모드로 시작합니다.

## 로그인

상단 **로그인**·**회원가입** 버튼으로 들어갑니다.

| 방법 | 설명 |
| --- | --- |
| 소셜 로그인 | 카카오·네이버·Google·Apple 버튼. `.env`에 앱 키가 있으면 실제 로그인, 데모에서는 체험용 회원으로 로그인합니다. 처음 가입하는 경우 약관 동의 화면을 거칩니다. 운영 서버에서는 키를 등록한 방식만 보입니다. |
| 이메일 로그인 | 가입한 이메일·비밀번호로 로그인합니다. 2단계 인증을 켠 운영진은 인증 앱의 6자리 코드도 입력합니다. |
| 테스트 계정 로그인 | 로그인 화면 하단 버튼을 누르면 바로 해당 대시보드로 이동합니다. |

| 테스트 계정 | 이메일 | 비밀번호 |
| --- | --- | --- |
| 사용자 | user@smilepoint.kr | smile1234 |
| 웹하드 관리자 (그린파일) | partner@smilepoint.kr | smile1234 |
| 웹하드 관리자 (클라우드박스) | cloud@smilepoint.kr | smile1234 |
| 최고 관리자 | admin@smilepoint.kr | smile1234 |

회원가입은 이름·이메일·비밀번호·휴대폰·추천인 코드와 필수/선택 약관 동의를 받습니다. 가입 축하 1,000 P(추천 코드 입력 시 +500 P, 추천인에게도 500 P)는 **첫 포인트 교환이 완료되면** 지급합니다 (다계정 가입으로 포인트를 모으는 악용 방지).

## 대시보드 기능

대시보드는 좌측 메뉴로 구성되며, 좌측 하단에 **메인으로** 버튼과 **프로필**이 고정되어 있습니다. 상단에는 알림(읽지 않은 수 표시)과 로그아웃이 있습니다.

**사용자**: 내 지갑(사용 가능·미확정·출금 가능·충전 잔액, 등급·출석·친구 초대·진행 중인 신청 단계 표시·14일 적립 차트·사용처 차트·지금 바꿀 수 있는 쿠폰) · 포인트 교환·확정(웹하드 계정 연결 — 웹하드로 전송된 6자리 인증번호 입력, 미확정 포인트 전액·일부 확정, 확정 요청 내역) · 포인트 충전(카드 등, 쿠폰 전용) · 계좌 출금(1원 인증으로 본인 명의 계좌 등록, 신청→심사→이체→입금 단계 추적, 이번 달/누적 실수령, 등급별 수수료, 일일 한도) · 포인트 쇼핑(검색·분류·수량) · 쿠폰함(번호 보기 후 바코드, 사용 완료/만료 탭 — 번호를 본 쿠폰은 직접 취소 불가) · 출석체크(월 달력, 7일 연속 보너스) · 포인트 선물 · 등급·이벤트(등급표, 진행 중 이벤트, 적립 방법, 받은 혜택 합계) · 거래 내역(필터·CSV) · 알림(전체 알림, 모두 읽음) · 고객센터(1:1 문의) · 프로필(사진 업로드, 알림 설정, 비밀번호 변경, 회원 탈퇴)

**웹하드 관리자**: 포인트 확정 요청(사용 승인·거절, 보낸 전환 내역, 전환 직접 등록) · 자사 개요(대기·승인·처리 시간 지표, 차트, 연동 상태) · 교환 요청(회원 연결 인증번호 목록, 일괄 승인/반려, 완료 30일 이내 회수) · 거래 내역 · 회원 현황(회원별 신청·승인·반려·누적 차감, CSV) · 정산 및 대사(기간별, CSV) · 통계 리포트(월별 승인 포인트·정산 금액, 요일·시간대별 신청, 상위 회원, 승인율) · API·연동(API 키 보기/복사/재발급, 웹훅 주소·테스트 전송, API 명세, 실제 호출·웹훅 전송 기록) · 교환 정책(일일 승인 한도·2차 승인 기준) · 2단계 인증. 자사 거래만 조회·처리할 수 있고, 회원 이름은 마스킹되어 보입니다.

**최고 관리자**: 운영 개요(회원·심사·출금·이체 실패 지표, 거래 추이, 제휴사 비중, 확인 필요 업무, 최근 가입·관리 기록) · 통계 리포트(회원 보유 포인트(부채), 누적 발행·소진·수수료, 월별 가입·교환·출금·쿠폰·수수료, 등급·가입 경로 분포) · 회원 관리(검색·필터, 회원 상세, 포인트 조정, 이용 정지, 계좌 인증 승인, 탈퇴 회원) · 제휴사 관리(신규 등록·API 키 발급, 교환 비율·최소 금액·일일 승인 한도·2차 승인 기준·운영 상태) · 운영진 계정(생성, 정지, 임시 비밀번호 발급, 2단계 인증 현황) · 연동 관리 · 교환 심사(2차 승인, 교환 회수) · 출금 심사·지급(심사 대기/이체 중/이체 실패/처리 내역 탭, 일괄 승인, 실패 건 재시도·수동 지급 완료·반려, 지급 계좌번호 열람 — 감사 기록) · 전체 거래 · 쿠폰 상품 · 쿠폰 주문 · 정산 및 대사 · 고객센터 답변 · 배너·공지 · 운영 설정(수수료·한도·출금 지급 방식·자동 승인 한도·적립 정책·선물 한도·점검 모드, 데모 초기화) · 감사 기록. 긴 목록은 50건씩 보여 주고 '더 보기'로 늘립니다 (CSV는 전체).

**프로필 이미지**: 계정마다 동물 캐릭터 30종 중 1종이 가입 시 무작위로 정해지며 선택할 수 없습니다. 사진을 올리면 사진이 우선 표시되고, 사진을 삭제하면 다시 캐릭터가 표시됩니다.

## 웹하드 포인트 전환 · 확정 흐름

웹하드 포인트는 **웹하드 쪽에서 전환을 신청**하면 넘어오고, 회원이 **확정**해야 사용할 수 있습니다.

1. **전환**: 웹하드 회원이 웹하드 사이트에서 스마일 포인트로 전환 신청 → 웹하드가 수수료(예: 50%)를 뺀 포인트를 `POST /api/v1/transfers`로 보냄 → 회원에게 **미확정** 포인트로 적립 (출금·구매 불가)
2. **확정**: 회원이 [포인트 확정]을 누름 (전액 또는 일부, 여러 웹하드 한 번에 전액 확정 가능) → 스마일 포인트가 웹하드에 웹훅 `points.confirm_requested`(사용 요청)를 보냄 → **승인 대기**
3. **승인**: 웹하드가 `POST /api/v1/confirmations/{id}/approve`를 호출 → **사용 가능** 포인트가 되어 출금 신청·쿠폰·상품권 구매 가능. 거절(`/reject`)하면 다시 미확정으로 돌아갑니다.
4. **정산**: 승인된 금액(스마일 1 P = 1원)이 해당 웹하드로부터 정산받을 금액입니다 (정산 및 대사 화면). 정산 주기는 계약 후 정합니다.

- 일부만 확정하면 먼저 들어온 전환부터 확정하고, 사용 요청에 웹하드 거래번호(`transferId`)별 포인트를 함께 보냅니다.
- 같은 `transferId`로 다시 보내면 적립하지 않습니다(재전송 안전). 같은 승인을 다시 보내도 한 번만 반영합니다.
- 웹하드는 아직 확정하지 않은 미확정 포인트만 `POST /api/v1/transfers/{transferId}/cancel`로 취소할 수 있습니다.
- 웹하드 장애로 승인이 오지 않으면 최고 관리자가 **교환·확정 심사**에서 대신 승인·거절할 수 있습니다 (웹하드에 웹훅으로 알림, 감사 기록).
- 제휴사마다 연동 방식을 고를 수 있습니다: **웹하드 전환**(기본) 또는 **교환 신청**(이전 방식 — 스마일 포인트에서 신청 → 웹하드 승인). 실제 웹하드 API 문서를 받으면 필드 이름·회원 확인 방식을 그에 맞춥니다.
- 데모: 사용자 화면의 **전환 신청(데모)** 버튼으로 웹하드 전환을 흉내 낼 수 있고, 그린파일을 뺀 제휴사는 확정 3초 뒤 자동 승인됩니다(그린파일은 웹하드 관리자가 직접 승인하는 예시).

## 포인트 충전 · 출금 수수료 · 수익

- **충전**: 신용카드·간편결제·계좌이체로 포인트를 충전합니다. 충전 포인트는 **쿠폰·상품권 구매 전용**이며 현금 출금·선물이 되지 않습니다. 구매할 때 충전 포인트부터 차감합니다. 운영 환경의 결제는 PG 계약 후 연동합니다 (그 전에는 데모의 모의 결제만 동작). 관리자는 사용하지 않은 충전을 취소할 수 있습니다.
- **출금 수수료**: 출금 금액 × 수수료율(부가세 포함, 기본 **5.5%**, 원 단위 반올림). **최소 출금 금액** 기본 **10,000 P**. 둘 다 최고 관리자 > 운영 설정에서 바꿉니다. 회원 등급별 수수료 할인은 선택 사항(기본 꺼짐)입니다.
- **수익**: 출금 수수료 + 쿠폰·상품권 마진(판매 포인트 − 공급가). 상품마다 공급가를 등록하고, 통계 리포트에서 월별 수수료·마진을 확인합니다.

## 웹하드 정산서

- 제휴사마다 **정산 주기**(주 1회 월~일 · 월 2회 1~15일/16일~말일 · 월 1회)와 **입금 기한**(기간 종료 후 N일, 기본 10일)을 정합니다 (최고 관리자 > 제휴사 관리 > 정책 수정).
- 정산 금액 = 기간 안에 웹하드가 사용 승인한(확정 완료) 스마일 포인트 합계 (1 P = 1원, 회수된 건 제외). 진행 중인 기간은 실시간 집계됩니다.
- 최고 관리자 > **웹하드 정산서**: 기간이 끝난 정산서를 발행 → 입금되면 **입금 확인**(금액이 다르면 메모 필수) · 입금 전이면 취소 후 재발행. 발행 후 회수 등으로 금액이 바뀌면 '발행 후 변동'으로 표시합니다. 기간 상세(확정 승인 내역)와 CSV를 볼 수 있습니다.
- 웹하드 관리자 > **정산서**: 발행된 정산서를 **확인**하거나 **이의 제기**(운영팀 알림). 자사 서버는 `GET /api/v1/statements` 또는 웹훅 `settlement.issued` · `settlement.canceled`로 받습니다.
- 운영 개요의 **자금 현황**에서 회원 보유 포인트(출금 가능·충전 잔액), 출금 처리 중, 미확정·승인 대기, 웹하드에서 받을 정산금, 이번 달 수익(출금 수수료 + 쿠폰 마진)과 카드 충전액을 한눈에 봅니다. 입금 기한이 지난 정산서·이의 제기·발행 대기 정산은 '확인이 필요한 일'에 표시됩니다.

## 그 밖의 운영 기능

- **회원 관리 메모**: 회원 상세에서 응대 기록 등을 남깁니다. 최고 관리자에게만 보이고 감사 기록에 남습니다. 회원 상세에서 해당 회원의 확정 요청과 **전체 거래 보기**로 바로 이동할 수 있습니다.
- **확정 요청 재전송·일괄 승인**: 웹하드가 웹훅을 놓쳤을 때 최고 관리자가 사용 요청을 다시 보낼 수 있고, 웹하드 관리자·최고 관리자는 대기 중인 확정 요청을 한 번에 승인할 수 있습니다.
- **거래 확인증**: 완료된 출금·충전·쿠폰·교환 거래는 거래 상세에서 확인증을 인쇄(PDF 저장)할 수 있습니다.

## 출금 지급대행(펌뱅킹) 연동

출금은 **신청 → 심사 → 계좌 이체 → 입금 완료** 순서로 진행되며, 회원과 관리자 화면 모두에서 단계를 확인할 수 있습니다.

| 지급 방식 (운영 설정) | 동작 |
| --- | --- |
| 수동 지급 | 관리자가 직접 송금한 뒤 `지급 완료`를 누르면 완료됩니다. |
| 지급대행 API | 관리자가 승인하면 지급대행사에 이체를 요청하고(상태 `이체 중`), 입금 결과가 오면 `완료`로 바뀌며 회원에게 알림이 갑니다. **자동 승인 한도**를 정하면 그 금액 이하 신청은 심사 없이 바로 이체합니다. |

- 지급대행사 계약 후 `.env`에 `PAYOUT_API_URL`, `PAYOUT_API_KEY`(필요 시 `PAYOUT_API_SECRET`, `PAYOUT_MERCHANT_ID`, `PAYOUT_WEBHOOK_SECRET`)를 넣으면 실제 이체로 바뀝니다. 요청·응답 필드 이름은 `payout.mjs` 한 파일에서 지급대행사 규격에 맞게 조정합니다.
- 이체 요청은 거래번호를 `Idempotency-Key`로 보내 같은 출금이 두 번 송금되지 않게 합니다. 응답을 받지 못하면 자동으로 다시 보내지 않고 `이체 실패(확인 필요)`로 남깁니다.
- 결과 통지 주소는 `{PUBLIC_URL}/api/payout/webhook`이며 `X-Payout-Signature: sha256=HMAC(PAYOUT_WEBHOOK_SECRET, 본문)` 서명이 맞을 때만 반영합니다. 통지가 1분 넘게 없으면 상태 조회 API로 확인합니다.
- 이체 실패 건은 관리자가 **재시도**, **수동 지급 완료**, **반려(포인트 복원)** 중에서 처리합니다. 이체 중에는 회원이 출금을 취소하거나 계좌를 바꿀 수 없습니다.
- 키가 없으면 데모 모드는 **모의 지급대행**(실제 송금 없음, 계좌번호가 0000으로 끝나면 실패 재현)으로, 운영 모드는 수동 지급으로 동작합니다.

## 서버 API

| 구분 | 주소 | 인증 |
| --- | --- | --- |
| 서비스 | `GET /api/health`, `GET /api/state`, `POST /api/action` | 세션 쿠키 + `X-SmilePoint: 1` 헤더 |
| 제휴사(웹하드) — 전환·확정 | `POST /api/v1/transfers` `{transferId, member, source, points}` (전환 전송), `GET /api/v1/transfers?status=unconfirmed\|confirming\|confirmed\|canceled`, `GET /api/v1/transfers/{transferId}`, `POST /api/v1/transfers/{transferId}/cancel`, `GET /api/v1/confirmations?status=pending`, `POST /api/v1/confirmations/{id}/approve`, `POST /api/v1/confirmations/{id}/reject` `{reason}`, `GET /api/v1/statements` (정산서) · 실패 응답의 `error`: `member_not_linked`, `invalid_amount`, `invalid_transfer_id`, `partner_inactive` 등 | `X-Api-Key` |
| 제휴사(웹하드) — 이전 방식·공통 | `GET /api/v1/exchanges?status=pending&limit=100&offset=0` (응답 `next`로 다음 페이지), `POST /api/v1/exchanges/{id}/approve`, `POST /api/v1/exchanges/{id}/reject`, `POST /api/v1/exchanges/{id}/reverse` (완료 30일 이내 회수), `GET /api/v1/link-requests` (회원 연결 인증번호), `GET /api/v1/settlements?date=YYYY-MM-DD`, `POST /api/v1/settlements/{YYYY-MM-DD}` (자사 합계 `{count, amount}` 제출 → 일치/불일치) | `X-Api-Key` (웹하드 관리자 > API·연동에서 확인) |
| 소셜 로그인 | `/auth/kakao`, `/auth/naver`, `/auth/google` | `.env`에 키가 있을 때 실제 OAuth, 없으면 데모 동의 화면 |
| 지급대행 결과 통지 | `POST /api/payout/webhook` | `X-Payout-Signature` HMAC 서명 |

회원 연결 인증번호(`member.link_requested`)·연결/해제, 교환 신청·취소·관리자 처리·회수, 테스트 이벤트는 제휴사 웹훅 주소로 전송합니다. 본문은 `X-SmilePoint-Signature: sha256=HMAC(API 키, 본문)`으로 서명하고, 실패하면 30초 간격으로 최대 3회 재시도합니다. 제휴사가 승인한 교환이 **고액(기본 10만 P 초과)이거나 제휴사 일일 승인 한도(기본 100만 P)를 넘으면** 바로 적립하지 않고 최고 관리자 2차 승인으로 넘깁니다 (API 응답 `review.status = "admin_review"`).

서버는 모든 요청에서 역할 권한을 다시 확인하고, 역할별로 볼 수 있는 데이터만 내려보냅니다. 사용자는 자기 거래만, 웹하드 관리자는 자사 교환과 마스킹된 회원 이름만 받습니다. 최고 관리자 화면 데이터에도 API 키 전체·계좌번호 전체·비밀번호 해시·OTP 키·인증번호는 들어가지 않습니다. 로그인은 같은 IP·이메일 5회, 같은 IP 30회, 같은 이메일(여러 IP 합산) 10회 실패하면 잠시 막습니다. 같은 요청이 3초 안에 다시 오면(더블클릭·중복 제출) 한 번만 처리합니다.

## 운영 모드와 보안

- `DEMO_MODE=off`로 처음 실행하면 샘플 회원·거래 없이 `ADMIN_EMAIL` 최고 관리자 1명으로 시작합니다. 기존 데이터에 기본 비밀번호(`smile1234`) 계정이 남아 있으면 자동으로 잠그고 로그인 세션도 끊습니다.
- 운영 모드에서는 웹하드 잔액을 임의로 만들지 않습니다. 교환 신청은 제휴사가 자사 장부를 확인해 승인할 때만 적립됩니다.
- 비밀번호를 바꾸거나 관리자가 초기화·정지하면 다른 기기의 로그인이 끊깁니다.
- 웹훅 주소는 https만 허용하고, 내부망·로컬 주소(IPv4 매핑·NAT64·6to4 등 IPv6 우회 표기 포함)는 등록 단계와 전송 직전 DNS 확인 단계에서 모두 막습니다 (DNS 재바인딩 방지).
- 웹하드 계정 연결은 제휴사를 통해 전달되는 6자리 인증번호로 본인을 확인합니다 (10분·5회 제한). 남의 아이디를 입력해도 연결·교환할 수 없습니다.
- 출금 계좌는 1원 인증(입금자명 숫자 4자리, 30분·5회 제한)을 거쳐야 등록되며, 계좌를 등록하면 이름을 바꿀 수 없습니다. `BANK_VERIFY_URL`이 없으면 최고 관리자가 명의를 확인한 뒤 승인합니다.
- 쿠폰 번호는 회원이 '번호 보기'를 누를 때 처음 공개하고, 번호를 본 쿠폰은 회원이 직접 취소할 수 없습니다.
- 운영진은 내 프로필에서 2단계 인증(TOTP — Google Authenticator 등)을 켤 수 있습니다. 최고 관리자가 꺼 두면 운영 개요에 경고가 뜹니다.
- 회원 탈퇴 시 이름·이메일·연락처·계좌·웹하드 연결을 즉시 파기하고, 거래 원장은 익명으로 보관합니다.
- 실패한 요청은 처리 전 상태로 되돌리고, 인증번호 오입력 횟수처럼 남겨야 하는 기록만 저장합니다.
- 가입은 같은 IP에서 1시간 3회로 제한하고, 추천인 보너스는 친구의 첫 교환이 완료된 뒤 지급합니다. 선물은 교환 이력이 있는 회원만, 하루 한도 안에서 보낼 수 있고, 같은 계좌는 한 계정에만 등록됩니다.
- 비밀번호 찾기는 30분짜리 재설정 링크를 만듭니다. `MAIL_WEBHOOK_URL`이 있으면 메일로 보내고, 없으면 서버 로그와 관리자 알림으로 남깁니다(데모 모드에서는 화면에 링크 표시).
- 점검 모드를 켜면 회원가입과 사용자의 교환·출금·구매·선물·출석이 막힙니다.

## 운영 전 남은 일

서버 저장소는 단일 서버용 JSON 파일입니다. 회원이 늘면 PostgreSQL 등 DB로 옮기고, 여러 서버로 늘릴 때는 세션 저장소를 분리합니다. 그 밖에 휴대폰 본인인증(PASS 등), 은행·PG 1원 인증(`BANK_VERIFY_URL`)과 지급대행사 계약 및 `payout.mjs` 규격 맞춤, 각 웹하드와의 회원 확인 방식 합의(인증번호 전달 또는 웹하드 OAuth), 기프티콘 공급사 API(실제 쿠폰 사용 여부 확인), Apple 로그인, 선불전자지급수단 등 규제 검토, 약관·개인정보처리방침 법률 검토가 필요합니다.
